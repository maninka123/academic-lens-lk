## Design system
Before any UI work, read App/design-system/DESIGN.md. Build only from its tokens (App/design-system/tokens.css, loaded via App/src/styles/index.css). Never hard-code a colour, font size, radius or shadow; if a value is missing, add a token to App/design-system/roles.json and rebuild. Check new screens in light and dark mode and at 390px. Do not name a component class after a Tailwind utility (e.g. `outline`).

## Privacy rules (permanent; read before touching data, import scripts, workflows or Git configuration)
This repository is **public**. Internal research evidence must never be committed, pushed or published, and must never enter Git history.
- **Never commit or push**: identity investigations, employment reviews, verification and evidence logs, correction/change histories, collection logs and checkpoints, unresolved or rejected-match lists, confidential research notes, candidate lists, worklists, raw exports, ethics documents, credentials or `.env` files. Examples: `identity_review.csv`, `employment_review.csv`, `field_evidence.csv`, `change_log.csv`, `research_unresolved.csv`, `rejected_*.csv`.
- **Where they live**: `Data/` (matched by the privacy patterns in `.gitignore`) and `private/`, plus the maintainer's private backup. Keep originals there. Never copy, symlink, commit, upload or print them into tracked files, public data, the frontend bundle, issues, PRs or commit messages. Never delete research evidence either.
- **Public data**: only the allowlist in `App/scripts/public-assets.mjs` may be published. Published free text (`notes`, `caution`, `qualificationReview`) must hold provenance and neutral context only: no investigation detail, remarks on someone's leave or employment, contact details or personal social-media links. `App/scripts/public-notes.mjs` enforces this at import. Do not widen the allowlist or weaken the sanitiser without the owner's approval.
- **Guards**: `App/scripts/privacy-guard.mjs` runs in the pre-commit and pre-push hooks and in CI. Never bypass it (`--no-verify`, editing `core.hooksPath`, deleting hooks, disabling the workflow step). If it blocks a legitimate file, fix the pattern in `FORBIDDEN_PATHS`/`ALLOWED_PATHS` and explain why. A new kind of internal file needs a `.gitignore` pattern, a `FORBIDDEN_PATHS` entry and a test (see `docs/PRIVACY_SAFEGUARDS.md`).
- **Git operations**: do not rewrite history, force-push, change repository visibility, create repositories or alter remotes without the owner's explicit approval, and back up first (`git bundle create <backup>.bundle --all`). Do not run `git add -f` on ignored paths.
- **Removals and structured fields**: apply accepted removals only with `node App/scripts/removals.mjs add` (private list, never published). Public `researchIdentities`, `researchObservations`, `metricEvidence`, status columns, `qualifications`, `interests`, names and positions must follow `App/scripts/public-notes.mjs`: no review or conflict wording, no profile recorded as a different person, no contact details, no remarks on leave. Tracked source CSVs follow the same rules (`App/scripts/redact-public-sources.mjs`).
- **Before finishing a change** that touches data, importers, workflows or Git config, run `npm run check:privacy` and `npm test`.

## Repository layout and the private study
- `App/` is the website (run npm commands from `App/`). `Data/` at the root is the only authoritative academic dataset; `App/public/data` is generated from it by `npm run data:import` and never edited by hand.
- `International-Doctoral-Training-Study/` is a **local, private research project**. It is git-ignored and blocked by the privacy guard. Never commit, push, copy into `App/public`, or reference it from the app. It reads `Data/` read-only through its own snapshot script and never writes research columns back. See docs/WORKFLOWS.md.
